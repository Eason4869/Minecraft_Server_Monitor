# v0.3.1 发布前复审

审查范围：v0.2.0 → v0.2.1 的五项修复，以及 v0.3.1 的包名、命令入口、品牌和打包调整。

结论：未发现五项修复引入的新 P1/P2 问题。复查以实际调用链和可重复的边界用例为依据，不能据此承诺不存在其他缺陷。

| 范围 | 核对结果 |
|---|---|
| 分群权限 | 采集、一言、渲染和分页之后按当前 UMO 重新过滤；部分退订后图片页作废，文字回退仅保留当前授权服务器；相同群号的不同实例不互相授权 |
| 通知重试 | 发送槽前后均检查授权与过期；5/15 秒退避从失败完成时计；成功群不重发；旧投递完成不删除替换后的新事件；最多三次 |
| 图片回退 | 图片阶段的 25 秒预算包含渲染锁等待，整次投递 50 秒为文字回退保留时间；渲染失败期间撤权或更改通知类型后不再发送 |
| 生命周期 | 卸载取消并等待活动渲染和锁等待任务，关闭后拒绝新任务并清空缓存；单个调用取消会释放锁，其他调用可以继续 |
| 禁用服务器 | 在保留完整服务器目录的前提下，可退订禁用服务器并清除关联默认值 |
| 品牌与资源 | 新包标识、注册标识、元数据和 ZIP 目录一致；图片署名 EasonClaw；Logo 与模板随安装包分发 |
| 指令入口 | 框架仅注册 `/mc`；全局控制在群聊和私聊都检查 AstrBot 管理员权限；分群设置仍要求在群内执行；重置与停止串行处理 |

新增 `tests/test_review_boundaries.py` 的 8 个参数化场景，覆盖部分撤权与图片失败叠加、等待一言期间撤权、通知渲染失败期间退订/关闭/改类型、等待发送槽期间撤权、取消调用后渲染锁释放。

新增 `tests/test_commands.py` 的 6 个指令场景，权限、生命周期和框架命令注册均通过实际函数调用验证。

本机验证结果：71 个测试通过，Ruff 检查及格式检查通过，Python 编译通过；9 张卡片截图通过几何与品牌检查，底部留白约 39px；23 个安装包文件通过 SHA256、源文件比对及解压导入检查。远程 CI 结果以仓库 Actions 为准。

验证命令：

```text
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
python -m compileall -q main.py minecraft_multi_monitor scripts tests
python scripts/preview_cards.py
python scripts/package_plugin.py
python scripts/verify_package.py
```

图片预览使用固定模拟数据和本机 Edge，复用生产模板与截图选项；检查 9 张截图的溢出、脚本转义、品牌、分页及底部空白。包校验逐文件比较源文件和 SHA256，并从解压后的 `data.plugins.astrbot_plugin_minecraft_monitor.main` 命名空间加载、初始化、核对群隔离和卸载。

验证边界：框架 API 使用替身；本机检查不包含生产 AstrBot、真实文转图服务和 QQ 适配器的端到端发送。已经交给平台的消息无法撤回；平台超时后重试仍可能重复。这些限制在 README 中保留说明。
